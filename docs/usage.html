Usage

Everything bugcap does, from the first capture to handing a report to your agent.

Install

Requires Python 3.10 or newer. Install it as a tool so the bugcap command is on your PATH:

# with the MCP server
pipx install 'bugcap[mcp]'
# or with uv
uv tool install 'bugcap[mcp]'

Leave out [mcp] for the core CLI only. The extra is needed just for bugcap mcp-serve. To update, run pipx upgrade bugcap or uv tool upgrade bugcap.

Set up a capture tool

bugcap calls an existing screenshot and annotation tool instead of reinventing one:

ToolPlatform
flameshotLinux, Windows, macOS (recommended)
satty + grimLinux (Wayland)
screencapturemacOS (built in)
bugcap setup              # reports the detected tool, or recommends one
bugcap setup --yes        # also installs it through your package manager

No capture tool? You can always import an existing image with bugcap capture --image PATH.

Scope captures to a project

Run this once inside a project repo. Reports captured there are tagged to the repo and listed only there.

bugcap init                                  # tag defaults to the folder name, GitHub slug to the origin remote
bugcap init --tag myproj --github owner/repo
bugcap init --images-repo owner/assets      # where synced image copies are committed

This writes .bugcap.toml in the repo. Change the values later with bugcap config repo show and bugcap config repo set. If the change alters the repo identity and reports already exist, bugcap asks whether to move them. In scripts, pass --migrate or --no-migrate.

Capture a bug

Capture launches your screenshot tool. Annotate, save, and bugcap asks for the description.

bugcap capture --title "Dashboard empty after module creation" \
               --note "Created Activity Tracking module, dashboard shows no widgets" \
               --tag ui
  • --title is a short summary.
  • --note is free text. Repeat --tag to add several tags.

Add more images

Import existing files, globs or URLs. Each is checked by its content (PNG, JPEG, GIF or WebP) and copied into the store.

bugcap capture --no-image --title "Typo on settings page" --note "says 'Setings'"   # text only, no screenshot
bugcap capture --image ./a.png --label login-error --title "Login fails" --note "See @i1 and @login-error"
bugcap attach <id> --image './shots/*.png' --image https://ci.example.com/run/42.png --label after-fix
bugcap attach <id> --image ./after.png --note "after the fix"   # the note is timestamped and tied to the image

Manage a report's images:

bugcap images <id>                              # index, label, kind, size
bugcap images <id> relabel login-error sign-in  # refused while notes reference it, unless --force
bugcap images <id> remove 2 --force             # rewrites @ references in the notes

Record the screen

Needs ffmpeg, or wf-recorder on Wayland. The default output is an animated GIF.

bugcap record --id <id> --format animated --max-seconds 10   # Enter or Ctrl+C stops early

Formats: animated (GIF), video, or frames (keyframes). Use --max-seconds, --max-mb and --fps to limit size. Without --id, the recording creates a new report.

Live mode: report many bugs in a row

A small always-on-top window sits in the top-right corner while you test. Needs tkinter and a desktop session.

  • Screenshot and Record (then Stop) each add a capture to a staged set. Stage as many images and videos as you like, in any mix.
  • New bug from N items turns the staged set into one report; refer to the items in the notes with @i1, @v2, and so on.
  • Add to existing bug attaches the staged set, plus an optional note, to a bug you already filed.
  • New bug (note only) files a bug with no media: a title, a note and optional tags.
  • Closing with staged captures or typed text offers to keep them as a draft, restored the next time you start live mode.
bugcap live
bugcap live --repo-dir ~/code/myproj        # scope reports to that repo's .bugcap.toml

List and triage

bugcap list                         # reports in the current repo
bugcap list --all                   # reports from every repo
bugcap show <id>                    # one report, with its images and resolved notes

bugcap edit <id> --status resolved --note "fixed in #42"
bugcap tag <id> add ui
bugcap tag <id> remove ui

bugcap delete <id>                  # asks first; --yes skips the prompt (images are removed too)

If a report ID is not found, the error suggests bugcap list --all to see report IDs across all repos.

Accepted statuses:

openin-progressresolvedclosedwontfix

References in notes

Point at a report's media, or at another report, from its notes:

WriteMeaning
@i1image 1
@v2video 2 (from record --format video)
@g3animated GIF 3
@f4frame set 4 (from record --format frames)
@login-errorthe media item with that label
#3report 3 (kept as text with a warning if it does not exist)
@@a literal @

Media references are checked when a note is saved: an unknown one is refused and the valid ones are listed. The number is the one show and images print. Older notes that use @1 still work. Code spans, fenced blocks and email addresses are never treated as references. show resolves them, and sync turns them into links or images in the GitHub issue.

Dashboard

A local web page to browse, filter and triage reports:

bugcap dashboard --open                 # http://127.0.0.1:8765 by default
bugcap dashboard --port 0               # pick a free port
Security: the dashboard listens on 127.0.0.1 only. --host 0.0.0.0 exposes all your bug reports to your network. Only do that on purpose.

GitHub

bugcap uses your gh login. Run gh auth login once if you haven't.

Import issues as reports

bugcap github pull --repo owner/repo --label bug --limit 20 --ask

Pulling is idempotent: running it again skips issues already imported. --ask prompts you to add a screenshot to each issue.

Push a report to an issue

bugcap sync <id> --to github --images-repo owner/assets --yes

This creates or updates the issue and commits a plain copy of each image to the images repo, so agents can read it. Media over the size limit is skipped with a warning. The limit is [sync] max_upload_mb, 25 MB by default.

Connect your agent (MCP)

The MCP server lets an agent list reports, read them (images included), request a screenshot, pull issues, attach images and update notes.

claude mcp add bugcap -- bugcap mcp-serve

Or add it to a project's .mcp.json:

{
  "mcpServers": {
    "bugcap": { "command": "bugcap", "args": ["mcp-serve"] }
  }
}

Tools

ToolWhat it does
list_reportsList reports, scoped to the current repo.
get_reportReturn a report with its image bytes, media metadata and resolved @ references.
request_screenshotAsk you to capture for a report or issue. Returns at once when there's no desktop.
pull_issuesImport GitHub issues as reports.
attach_imageAttach paths, globs or URLs, with optional labels.
update_notesUpdate notes. Invalid @ references come back as JSON with a code.

Logs

The server logs to logs/mcp-server.log in the data directory (rotated, 1 MB × 3) and to stderr. Stdout is reserved for the protocol. Set the level with --log-level, BUGCAP_LOG_LEVEL or [log] level in config.toml. Note text is only logged at debug.

Where data lives

Reports and images are plain files, independent of any tracker.

PlatformData (bugcap.db, images/)Config (config.toml)
Linux~/.local/share/bugcap~/.config/bugcap
macOS~/Library/Application Support/bugcapsame as data
Windows%LOCALAPPDATA%\bugcap%APPDATA%\bugcap

Set BUGCAP_HOME to move both. Reinstalling bugcap never touches your data. Schema changes are migrated in place.
